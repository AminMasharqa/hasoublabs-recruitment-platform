# Portfolio Spec

## Requirements

Use `templates/requirements.md`. Give every requirement an ID and observable evidence. Cover content integrity, recruiter comprehension, responsive layout, keyboard access, links, metadata, and non-goals. Run requirement analysis, then stop for human approval.

## Design

After approval, use `templates/design.md`. Preserve the stack and define content sources, component boundaries, responsive rules, accessibility behavior, and verification.

## Tasks

Use `templates/tasks.md`. Each task changes one coherent concern, maps to requirement IDs, names likely files, and defines evidence. Stop again before implementation.

Use `references/requirements-catalog.md` for examples, not as automatic scope.
