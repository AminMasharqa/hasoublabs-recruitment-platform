# Implementation Plan: HasoubLabs Recruitment Platform (Phase 1)

## Overview

This plan converts the Phase 1 design (Requirements 1–4, 4A, 5–9, 28, 29) into incremental coding steps for a Python/FastAPI modular monolith backed by PostgreSQL. The order is dictated by the dependency structure in the design: the platform layer (`db`, `security`, `storage`, `mail`, `notifications`, `jobs`, `i18n`, `taxonomy`, `pagination`) is built first because every domain module imports it one-way; the `audit` capture machinery follows because every mutation flows through it; then the domain modules are built in dependency order (`identity` → `profiles`/`cvs` → `jobs` → `applications` → `reviews` → `reporting`).

Each domain guarantee that the design expresses as a Correctness Property is turned into its own property-based test sub-task (Hypothesis, ≥100 iterations), annotated with its property number and the requirement clauses it validates. Test sub-tasks are marked optional with `*`. Core implementation sub-tasks are never optional. Checkpoints appear at natural integration boundaries.

Conventions carried from the design: module layout is `router.py / api.py / service.py / repository.py / models.py / schemas.py / errors.py`; a module may import another only through its `api.py`/`schemas.py`; `platform/*` never imports a domain module; domain logic never imports `fastapi` outside `router.py`; every route declares an authorization guard.

## Notes

- Tasks marked with `*` are optional test tasks and can be skipped for a faster MVP; core implementation tasks are never optional.
- Each task references specific requirement acceptance criteria for traceability.
- Property tests use Hypothesis at ≥100 iterations; each property from the design is implemented by exactly one property test, tagged with its property number and validated requirement clauses.
- Reference implementations for model-based properties (14, 23, 32, 50, 51) are written independently of production code.
- Property 4 (timing) runs in a dedicated serialized CI stage, isolated from the parallel suite.
- The `audit` capture, hash chain, and separate-connection failure entry (Section 9) precede all domain modules because every mutation depends on them.
- Integration tests use Testcontainers (PostgreSQL, Valkey, MinIO, ClamAV, Mailpit) since a large share of guarantees are DB- or storage-enforced.
